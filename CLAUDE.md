# All In Ascent — notes for Claude

## Local and online play must stay in sync

- All game rules live in `engine/` (`state.js`, `engine.js`, `helpers.js`). Local hot-seat play, online play (PartyKit, `party/game.js`) and the bots (`sim/`) all run this one engine.
- `game.js` holds the GAME DATA (source of truth for characters, routes, gear) and the UI only. Never add a rule, formula or legality check to `game.js` or `online-mode.js`: ask the engine (`AscentEngine.getLegalActions`, `findLegalAction`, `explainIllegalAction`, helpers) and present the events `applyAction` emits.
- The browser loads the engine as `engine/engine.browser.js`, generated by `engine/build-browser.js` (it must keep working from `file://`, so no ES module imports in the browser scripts). After changing `engine/*.js` or the GAME DATA section of `game.js`, run `npm run data:build` and commit the regenerated `engine/data.js` and `engine/engine.browser.js`.
- If something the UI needs is missing from the engine (a value, an event field, a reason string), add it to the engine rather than computing it in the UI.
- Card availability comes from `getLegalActions` (game.js `isLegalNow`); the text on an unavailable card comes from `illegalActionReason` (a `code` plus details), which game.js `uiBlocker` only words. Never re-check costs, gear or occupancy in the UI to decide or explain.

## Before committing

Run `npm test` (lint with zero warnings, generated-file check, engine unit tests, PartyKit smoke test, Playwright end-to-end tests) and fix every failure. Add tests with every change:
- rule changes: assertions in `engine/test-*.js`;
- UI or flow changes: a Playwright spec in `tests/e2e/`. Local-play specs must keep checking that a UI-played game replays identically through the engine (`replayInEngine` in `tests/e2e/support.js`).

Rule changes that alter outcomes get a note in `engine/version.js`.
